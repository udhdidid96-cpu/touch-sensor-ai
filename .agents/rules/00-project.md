# Project2 — always-on rules

Scope: the whole workspace. Set this rule to **Always On**.

Full context is in `AGENTS.md` at the repo root — read it once at session start.
This file is the short version an agent must never violate.

## What this project is

A capacitive touch-sensor dressing (25 pads, 90 × 120 mm) that warns before an
intubated patient pulls their tube. It is a research prototype. It has **not**
been assessed against IEC 62304 and is not a medical device. Write about it that
way — in code comments, in the UI, in commit messages.

## The nine things that must stay true

1. The browser renders; the server classifies. No thresholds, no severity
   decisions, no pad-lift counting in `app.js` or `web_serial.js`.
2. Nothing hand-codes a probability inside `classify_deltas()`.
3. No invented patient identity: no names, no `HN-#####`, no `ICU-A-###`,
   no `ETT #`, no populated ward. Empty slots stay empty.
4. Numbers on screen are measured from `/api/v6/metrics` or they are blank.
   Never type a figure into markup.
5. `SPEC_DETACH_MAX` is 25000. The honest finding is that 0 of 81 recordings
   meet the detachment spec — do not tune the constant until they do.
6. `--allow-public-no-key` never enters the Dockerfile.
7. No emoji in the console or the server's status strings.
8. `not been assessed against IEC 62304` stays in both `index.html` and
   `app.js`.
9. `Data/metrics.json` is generated by `--verify-metrics`, never edited.

## Before you say something works

Run it. `python -m pytest tests/ -q` must report **0 failed**. If you touched
the model, also `python main.py --verify-metrics`. Quote the actual output;
do not describe what you expect it to say.

## Do not

- Add another launcher `.bat`. There are four and there were six.
- Edit anything under `Data/<class>/`. Those are the bench recordings.
- Run two agent sessions against this folder at once — two sessions overwrote
  each other mid-commit on 2026-08-19.
