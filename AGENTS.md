# Project2 — Smart Extubation Early Warning

A 25-channel capacitive touch-sensor dressing that warns before an intubated
patient pulls their tube out. FastAPI backend (`main.py`), browser console
(`web/`), scikit-learn classifier, 81 bench recordings under `Data/`.

This file is the contract for any agent working in this repo. It exists because
the same defects came back three times, each one past where the previous guard
was looking. Read the invariants before changing anything.

## Run it

```bash
python main.py                 # dashboard on 127.0.0.1:8081
python -m pytest tests/ -q     # 113 tests, must stay green
python main.py --verify-metrics # re-measure and diff Data/metrics.json
python main.py --audit DIR     # corpus audit incl. the lift-gate criterion
python main.py --monitor COM5  # terminal live monitor on a serial port
```

## Invariants — do not break these

These are not style preferences. Each one is a defect that shipped, was fixed,
and came back.

**1. The browser never classifies.** Severity, CPRI and pad counts come from the
server. `app.js` and `web_serial.js` are greppted by CI for `nLifted`,
`rawLevel`, `liveKalman`, `isCriticalDetached`. A second classifier in the page
disagreeing with the server is worse than no classifier.

**2. Nothing hand-codes a probability in `classify_deltas()`.** A hand-written
cascade was reintroduced *inside* that function, so it reached every serving
path at once while `compute_oof` and `evaluate_stream` called the model
directly — meaning no published figure ever measured it. `t_no_handcoded_proba`
compares output against `full_proba()` frame by frame.

**3. No invented patient identity, anywhere.** No names, no `HN-#####`, no
`ICU-A-###`, no `ETT #`, no fabricated ward. Bed slots return
`patient_id: None` and `cpri_percent: None` until an operator types something.
An 8-bed ward of invented Thai patients has been removed twice.

**4. Displayed numbers are measured or absent.** The four `data-metric` slots in
`index.html` must contain no digit in the markup, must be visible (never inside
a hidden container), and must be filled at runtime from `/api/v6/metrics`. If
the API cannot answer, they stay blank — never a remembered value.

**5. `SPEC_DETACH_MAX` is 25000** and the audit label is an f-string of the
constant. Raising it to 28500 makes the corpus "pass" the detachment spec
including bare-baseline files, because resting attached sits near 28000. The
honest finding is 0/81 at 25000: **the spec does not describe this patch.**

**6. The Dockerfile must never carry `--allow-public-no-key`.** `main.py`
refuses a non-loopback host unless `PROJECT2_ACCESS_KEY` is set, because the API
serves every recording, accepts uploads, and accepts audit-trail writes. That
flag once sat in the CMD while the comment above it said not to add it.

**7. No emoji** in `index.html`, `app.js`, `web_serial.js`, or the server's
status strings.

**8. "certified" only in a negated context.** The sentence
`not been assessed against IEC 62304` must appear in both `index.html` (visible
to a viewer) and `app.js` (as running code). A `console.info` alone is not a
disclaimer anyone can read.

**9. `metrics.json` must reproduce.** `--verify-metrics` re-measures and diffs.
It was once six days and one model stale.

## Model — current configuration

Decided 2026-08-19. Do not change without re-measuring and saying so.

- **HistGradientBoosting**(`max_iter=150, max_depth=8, class_weight="balanced"`)
  on **34 features** = 25 pad deltas + 9 statistics.
  `_new_rf` keeps its name for call-site compatibility only; it is not a forest.
- **Annunciator: 7-of-6, hold 9.** 100% episode sensitivity, 7.8 alarms/hour.
- Measured leave-one-file-out over the 81 recordings: **97.53% file accuracy.**

**Do not revert to the 9-statistic feature set.** At an equal alarm budget it
detects 70% of episodes against 100%.

## Sensor facts that are easy to get wrong

- The lift gate is **−300 counts** per pad; the noise gate is **60 counts**.
  Any other threshold in the code is somebody's invention.
- **Horizontal pull produces no lift signal.** It reads as a press. A rule that
  says "positive press and no deep lift means touch" forces every horizontal
  pull to Level 1.
- `PAD_ORDER` is resolved from `Data/Press/1_by_1.csv`. Recordings use
  `Sensor-N == pad N`; the **live serial path is still unverified in both
  directions** — both sockets default to `permute=0`.
- Single session (S0). These figures cannot show generalisation to a new sensor
  mounting. Say so rather than implying otherwise.

## Working rules

- **Run one agent session at a time on this folder.** Two concurrent sessions on
  2026-08-19 overwrote each other mid-commit.
- **Measure before claiming.** Every number in `README.md`, `METRICS.md` and the
  console is reproducible from the corpus. If you change the model, re-run
  `--verify-metrics` and update them in the same change.
- **A guard that greps for a name is not a guard.** The ward fabrication came
  back under a new CSS class; the metrics guard passed on four hidden em dashes.
  Anchor tests on behaviour or on a stable attribute, not on a literal.
- Do not add a new launcher script. There are four, and there were six.
